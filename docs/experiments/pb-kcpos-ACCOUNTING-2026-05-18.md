## 8. 每次新 PB 任务是否"干净无污染环境"(诚实四轴,2026-05-18 补)

> §1–7 写时此澄清是散的/不完整的;此节为合并明确版,以免重要诚实保留只活在对话里。

按现在 Option B 逻辑(每任务从 pristine `:task_cleanroom` 镜像 `docker run` 全新容器、全新 workdir、kcpos 以非 root `agent` 跑、参照 `---x--x--x` 对 agent 不可读):

**轴1 跨任务状态:干净 ✅(结构性)。** 每任务全新容器/workdir,无共享 module 缓存、无跨任务克隆残留,模型本身无跨任务记忆。按逻辑成立。

**轴2 镜像源码泄漏:不保证 ⚠️(目前靠我手动,非结构)。** `:task_cleanroom` 带 `.git`(法医:~4/19 快照,可能含原始源码史)。Option B 设置里 `rm -rf /workspace/.git` 去掉了这一向量——**但这是脚本一行手动步骤,我只查了 /workspace,未穷尽核实镜像别处无源码/参照未 strip 的调试符号。** "干净"=依赖我清理得全,正是"靠我每次不出错"的脆弱模式。结构化需:经核实、脚本化、被审计的镜像消毒 + 校验参照已 strip + 无源码于他路径。

**轴3 联网→compile.sh 抓源码:只检测不预防 ⚠️。** 容器必须有网(给 LLM)。agent 无 bash 不能直接 curl,但 compile.sh 是 agent 写、网可达 → 有动机模型仍能借 compile.sh 抓上游源码。**pb-audit 事后抓到→分作废,但不是硬墙、非"不可污染"。** 硬墙需把构建隔成 `--network none` 子步骤——早先桥接版有,现"原生跑容器内"版**没有**(为给 LLM 留网)。此张力不粉饰。

**轴4 模型记忆污染:环境根本治不了 ❌(正交、最深)。** cmatrix 那种是上游实现已在模型权重里——再干净的容器无效,污染在权重不在环境。**故"干净环境"≠"干净测量":著名程序(cmatrix/tty-clock)无论容器多干净都被记忆污染;entr 这类相对安全。** 只能靠"选非著名任务 + pb-audit + 诚实标注",不能靠环境。

**结论:** 跨任务状态结构性干净;**整体不是"保证无污染"**——轴2 靠我手动(应脚本化+审计才结构化)、轴3 只检测不预防(要硬墙需重隔离构建网络)、轴4 环境层无解。**任何 PB 分必须随附此四轴限定;尤其轴4:对著名任务,分高不代表能力,代表记忆。** 这是这条实验链对外引用时必须并读的硬约束。
